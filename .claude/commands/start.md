את/ה מקים/ה עכשיו עוזר אישי בטלגרם בשביל מישהו שעובד ב-Claude Code. ייתכן שהוא לא מכיר את GitHub, את Vercel או את BotFather.

**העיקרון:** כל מה שאפשר להריץ במחשב, את/ה מריץ/ה בעצמך: Git, GitHub CLI, Vercel CLI, יצירת קבצים, סיסמה ובדיקות. **באתרים המשתמש לוחץ בעצמו** (BotFather, ספק ה-AI, אישורים בדפדפן). אין טייס אוטומטי באתרים, ולא פותחים דפדפן בשבילו. בכל פעולה שלו אומרים בדיוק על מה ללחוץ, במשפט או שניים.

## שאלה אחת בהתחלה
ב-AskUserQuestion: **"כמה הסבר אתה רוצה בדרך?"**
- **הסבר קצר לכל שלב (מומלץ)**: משפט "למה" לכל שלב, ולכל מונח חדש (ראו `docs/glossary.md`).
- **רק מה לעשות**: בלי הסברים, אלא אם שואלים או שמשהו נתקע. הבדיקות לא מתקצרות.

## 0. העותק של הקוד
אם התיקייה הנוכחית היא כבר הערכה (`package.json` עם `"name": "telegram-assistant"`), מדלגים לשלב 1.

אחרת (המשתמש הדביק את השורה בתיקייה אחרת):
1. `gh auth status`. **אם מחובר, לא יוצרים כלום לפני ששואלים.** ב-AskUserQuestion: "ליצור את העותק של הקוד בחשבון GitHub ‏**<שם המשתמש>**?". האפשרויות: "כן, בחשבון הזה" ו"לא, בחשבון אחר". אם יש כמה חשבונות מחוברים, מציגים את כולם. מחשב של עבודה מחובר לפעמים לחשבון של העבודה, והבוט האישי לא צריך לשבת שם.
   - **חשבון אחר:** אם הוא מופיע ב-`gh auth status`, מריצים `gh auth switch -u <שם>`. אם לא, המשתמש מריץ `gh auth login --web` ומתחבר בדפדפן לחשבון הנכון. בודקים שוב ב-`gh auth status`.
   - אחרי האישור: `gh repo create telegram-assistant --template roshilabs-hq/telegram-assistant --private --clone`. אם השם תפוס, `telegram-assistant-2` וכן הלאה.
2. אם GitHub CLI לא מחובר: מבקשים מהמשתמש להריץ בטרמינל `gh auth login --web` ולאשר בדפדפן. אם אין GitHub CLI בכלל: שולחים לו את הקישור https://github.com/new?template_name=telegram-assistant&template_owner=roshilabs-hq, אומרים לבחור **Private** וללחוץ **Create repository**, ואז לשלוח לך את הכתובת. משכפלים עם `git clone`.
3. מכאן כל פקודה רצה בתוך התיקייה החדשה. **לפני כל commit** בודקים `git config user.email`. אם ריק, מבקשים את המייל שאיתו נרשם ל-GitHub ומגדירים אותו (Vercel בתוכנית החינמית חוסם קומיט של מחבר אחר).

## 1. מה מותקן
`node scripts/setup.mjs preflight`. מטפלים בכל ❌ לפני שממשיכים:
- **Vercel מחובר:** שואלים ב-AskUserQuestion: "להעלות את הבוט לחשבון Vercel ‏**<השם מהבדיקה>**?". האפשרויות: "כן" ו"לא, לחשבון אחר". **בחשבון אחר:** מריצים `node scripts/setup.mjs login`, ומתחברים בדפדפן לחשבון הנכון. אחר כך מריצים שוב את `preflight`. בדרך כלל חשבון Vercel צריך להיות מחובר לאותו GitHub שבו נוצר העותק.
- **Vercel לא מחובר:** `node scripts/setup.mjs login`. אומרים למשתמש שיפתח דפדפן, ושם מאשרים (אין חשבון? נרשמים שם עם GitHub). **לא מריצים `vercel login` ישירות**, כי בלי הסקריפט הוא קורס כששם המחשב בעברית.
- **Node ישן מ-20:** מבקשים להתקין את גרסת ה-LTS מ-https://nodejs.org ולפתוח מחדש את VS Code.

## 2. שני דברים שרק המשתמש יכול לעשות
1. `node scripts/setup.mjs env`. הפקודה יוצרת את `.env.local` ואת סיסמת ההקמה. פותחים לו את הקובץ: `code .env.local`.
2. **הבוט בטלגרם:** לפי "בקצרה" ב-`steps/01-create-bot.md`. מדביקים את הטוקן ב-`TELEGRAM_TOKEN` בקובץ.
3. **מפתח ה-AI:** קודם שואלים ב-AskUserQuestion איזה ספק, ו-Gemini ראשון עם "(מומלץ)". את העלות של כל ספק לוקחים מהטבלה ב-`steps/02-ai-key.md`, ולא כותבים מספרים מהזיכרון. אחר כך עובדים לפי `steps/02-ai-key.md`, כולל חיבור אמצעי תשלום ו**תקרת הוצאה**. את פרטי הכרטיס המשתמש מזין בעצמו באתר של הספק. מדביקים את המפתח ב-`AI_API_KEY` בקובץ.
4. כשהוא אומר ששמר: `node scripts/setup.mjs verify`. על כל ❌ עונים לפי ההודעה, ומריצים שוב.

## 3. העלאה לאוויר
`node scripts/setup.mjs deploy`. הפקודה יוצרת פרויקט ב-Vercel, מחברת אותו ל-GitHub (בשביל העדכונים), מחברת Supabase בפרנקפורט, מעבירה את שלושת הסודות ומעלה.
- **אם Supabase מבקש אישור** ונפתח דפדפן: המשתמש מאשר שם, ומריצים את `deploy` שוב. הפקודה ממשיכה מאיפה שעצרה.
- בסוף הכתובת של הבוט נכתבת לבד ל-`.env.local` (`KIT_URL`).

## 4. הפעלה וחיבור
1. `node scripts/setup.mjs activate`. הפקודה יוצרת את הטבלאות, מחברת את הבוט לטלגרם ומפעילה את התזכורות. בסוף היא מדפיסה קישור חיבור.
2. נותנים למשתמש את הקישור: פותחים בטלפון ולוחצים **Start**. הבוט עונה "🎉 מחוברים!".
3. מבקשים ממנו לשלוח לבוט "תזכיר לי בעוד 2 דקות לשתות מים". אחרי שהתזכורת מגיעה, ההקמה גמורה.

## חוקים
- **לא יוצרים כלום בחשבון שהמשתמש לא אישר בשיחה הזו**: לא עותק ב-GitHub, לא פרויקט ב-Vercel ולא מסד נתונים. חשבון שמחובר במחשב הוא לא אישור.
- **עברית**, חם וישיר. בתחילת כל שלב: שם השלב וכמה זמן הוא לוקח, במשפט אחד. בסוף כל שלב: מה הבא.
- **סודות:**
  - לעולם לא קוראים ולא מדפיסים את `.env.local`. רק הסקריפטים קוראים אותו, והם מדפיסים כן/לא בלבד.
  - לא מבקשים טוקן, מפתח או סיסמה בצ'אט.
  - אם הודבק סוד בצ'אט, אומרים בעדינות להחליף אותו אצל הספק.
- **תקלות:** קודם "נתקעתי" בקובץ השלב המתאים ב-`steps/`. אחר כך `npm run check`, שמראה מה ירוק ומה אדום בבוט החי.
- **לא משנים את `CHECKLIST.md`.** הוא נוצר אוטומטית.
